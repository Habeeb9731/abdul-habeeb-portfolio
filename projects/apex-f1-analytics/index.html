Overview

F1 produces huge amounts of data. APEX turns a season of it into something you can actually read.

OpenF1 publishes timing, positions, laps, stints and telemetry for every session since 2023 — but as raw API responses. APEX is a dashboard that turns that into season overviews, race replays, head-to-head driver comparisons, tire strategy charts and championship tables, with no account or paid API needed.

Challenge & solution

What made it hard, and how I approached it.

The challenge

Raw, heavy and inconsistent data

  • Telemetry for a single session can run to hundreds of thousands of points per driver.
  • Standings, positions and weather arrive as separate endpoints with gaps and missing snapshots.
  • An AI assistant needed to be useful without exposing API keys or running up costs.
The solution

Fetch less, cache more, explain clearly

  • Telemetry loads two drivers for a five-minute window at a time, filtered at the API and downsampled before charting.
  • Requests are cached and cancelled when abandoned (TanStack Query); selections live in the URL so views are shareable.
  • Ask Apex runs server-side behind GitHub sign-in, with a daily per-user question limit stored in SQLite.

How it works

Under the hood.

  • DataOpenF1 historical API (2023 onward) — meetings, sessions, laps, stints, positions, telemetry, weather.
  • FrontendReact + TypeScript on Vite, TanStack Query for caching and cancellation.
  • BackendNode server for GitHub OAuth and the AI analyst; usage counts in SQLite.
  • DeploymentDocker, served through a Cloudflare Tunnel at apex.abdulhabeeb.com.

Takeaway

What I learned.

Working with real sports data is mostly about deciding what not to load. Designing around windowed, downsampled requests made the dashboard fast — and taught me to treat API limits as a design constraint, not an afterthought.
